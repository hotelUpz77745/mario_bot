# Единый Протокол Сущностей и Настроек (`MarioBot` + `MarioBacktest`)

Документ фиксирует строгие правила конфигурации, единиц измерения, математику торгового движка `4H CHoCH` и инварианты 1-минутного симулятора, обеспечивающие 100% паритет между боевым ботом (`MarioBot`) и бэктестером (`MarioBacktest`).

---

## 1. Протокол настроек (Settings Protocol)

1. **Strict Dict Access:** все модули читают словари конфигурации строго через `cfg["key"]`. Использование `.get("key", default)` в боевой и симуляционной логике запрещено — любая опечатка или пропуск обязательного поля обязаны падать с `KeyError` на этапе инициализации.
2. **Политика дефолтов (`None` vs `0`):**
   - Безопасный маркер отключённой опции — `null` в JSON (`None` в Python).
   - Значение `0` или `0.0` в качестве неявного дефолта запрещено. Если в конфиге задаётся `0.0` (например, нулевой буфер или нулевое проскальзывание), оно должно быть прописано явно с пояснением `_desc_*`.
3. **Single Source of Truth (SSOT):**
   - `MarioBot/CFG/app.json` — системные настройки, список символов (`ADAUSDT`, `SOLUSDT`, `XRPUSDT`, `DOGEUSDT`, `ETHUSDT`, `LTCUSDT`), спецификации инструментов и пути.
   - `MarioBot/CFG/strategies/<passport_id>.json` — полный паспорт стратегии.
   - `MarioBacktest/CFG/backtest.json` — исключительно параметры стенда симуляции (диапазоны дат IS/OOS, комиссии, проскальзывание, директория кэша). Паспорт стратегии **не дублируется** в `backtest.json`.
4. **Семантика единиц измерения:**
   - `_ratio` / `_rate`: строго **доля от единицы** (`0.0005` = `0.05%`, `0.01` = `1.0%`, `1.0` = `100%`). Вся внутренняя математика ядра и бэктеста работает исключительно в долях.
   - `_pct`: строго **проценты от 100** (`0.50` = `0.5%`, `50.0` = `50%`). Применяется только в выходных полях аналитики (`roi_pct`, `winrate_pct`, `max_drawdown_pct`).
   - Время: `_ms` для epoch timestamp в миллисекундах, `_sec` для интервалов в секундах, `_days` для дней, `_candles` для баров.
   - Запрещена любая эвристическая «автонормализация» значений.
5. **Документирование конфигов (`_desc_*`):** каждый числовой и логический параметр в JSON снабжается соседним полем `_desc_<name>` с единицей измерения и числовым примером.
6. **Стандарты кода:**
   - В начале каждого файла шапка `# Path: ...` и `# Role: ...`.
   - Все `import` строго вверху файла (0 инлайн-импортов).
   - Размер файла: целевой `150–450` строк, жёсткий предел `600` строк.

## 2. Паспорт стратегии `4H CHoCH` (Каноническая схема)

Каждая версия паспорта в `MarioBot/CFG/strategies/*.json` обязана содержать секции:
- `strategy_id`, `enabled`, `symbols`, `timeframe` (`"4h"`).
- `capital`: `start_balance_usd`, `leverage`, `max_open_positions`, `risk_per_trade_ratio` (или `null`), `fixed_notional_usd` (или `null`).
- `swing_detector`: `left_candles`, `right_candles`, `min_swing_sequence`.
- `session_window`: `enabled`, `timezone` (`"America/New_York"`), `start_time` (`"08:00"`), `end_time` (`"16:00"`), `weekdays_only`.
- `trend_fatigue_filter`: `enabled`, `lookback_days` (`3`), `min_net_efficiency_ratio`, `max_counter_pullback_ratio`, `block_mode`.
- `choch_determinator`: `breakout_price_source` (`"close"`), `require_sweep` (`false`), `entry_order_type` (`"MARKET"`).
- `risk_management`: `sl_anchor` (`"origin_swing_extreme"`), `sl_buffer_ratio` (`null` или доля, напр. `0.0010`), `tp_rr_ratio` (`1.0`), `soft_stop_enabled` (`false`).

## 3. Инварианты 1-минутного движка симуляции (`MarioBacktest`)

1. **Единый оркестратор:** `MarioBacktest` исполняет тот же класс `TradeEngineOrchestrator` и те же классы-рудименты из `MarioBot/CORE/`, заменяя лишь `ExecutionBroker` на `SimExecutionBroker`.
2. **Таймфрейм решений vs гранулярность исполнения:**
   - Агрегатор `CandleAggregator` собирает `4H` свечи из потока `1m` свечей по строгим границам UTC (`00:00, 04:00, 08:00, 12:00, 16:00, 20:00`).
   - Решение принимается строго после закрытия `4H` свечи; `MARKET`-вход исполняется по цене `open` следующей 1m свечи с учётом `slippage_rate` и `taker_fee_rate`.
3. **Пессимистичный порядок внутри 1m свечи:**
   - На каждой минутной свече проверка `Stop-Loss` выполняется **до** `Take-Profit`.
   - Если внутри одной 1m свечи задеты оба уровня (`low <= sl` и `high >= tp` для `LONG`, или `high >= sl` и `low <= tp` для `SHORT`), сделка безусловно закрывается по `SL` как убыточная.
4. **Запрет look-ahead в свингах:**
   - Фрактал с `right_candles = R` становится известен торговому ядру строго на закрытии бара `t + R`, а не в момент формирования экстремума `t`.
